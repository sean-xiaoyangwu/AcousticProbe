## 一、算法重构：从 centroid 到绝对距离追踪

### 背景

上一版（2026-04-25）的 Step 6 使用 energy-weighted centroid 计算"运动重心距离"，
存在两个问题：
1. 语义不直觉——用户希望看到的是主要运动体的**绝对远近变化**，而非加权平均
2. 近场泄漏（<0.25 m）的高振幅会污染重心计算，导致整体偏近

### 修改（Step 6）

替换为**窗口 argmax 绝对距离追踪**，完全借鉴 6.808 Lab 4 笔记本的思路：

```python
PEAK_WIN = 80               # ±80 bins ≈ ±86 cm
win_lo = max(0, target_bin - PEAK_WIN)
win_hi = min(max_range_idx, target_bin + PEAK_WIN)

win_slice  = diff_bg[:, win_lo:win_hi]
local_peak = np.argmax(win_slice, axis=1)
global_peak = (local_peak + win_lo).astype(float)

sm_peak = signal.medfilt(global_peak, MED=7)
sm_peak = moving_average(sm_peak, MA=5)
tracked_dist_m = range_axis[sm_peak.astype(int)]   # 单位：米
```

输出为每帧主要运动反射体的绝对距离（米），plot 3 显示随时间的位置曲线。

## 二、Noise-gated 追踪（hold-last-value）

### 问题

argmax 在安静期（帧差接近零）各 bin 振幅相近，argmax 随机跳 bin，
导致追踪曲线持续大幅抖动（±60 cm），无法分辨运动与噪声。

### 解决方案

引入**噪底自适应阈值门控**：

```python
noise_floor   = np.percentile(win_max, 30)   # 30th 百分位估计静止噪底
MOTION_THRESH = motion_threshold * noise_floor  # 默认 3.0×

last_valid = float(target_bin)
for i, (mx, pk) in enumerate(zip(win_max, local_peak)):
    if mx > MOTION_THRESH:
        last_valid = float(pk + win_lo)   # 有运动→更新
    global_peak[i] = last_valid           # 无运动→保持上一有效值
```

逻辑：峰值帧差低于阈值时，位置冻结在上一个有效值（hold-last-value），
不引入随机跳变；高于阈值时正常更新。

### 验证：raw argmax 叠加对比

在 Plot 3 上加入灰色半透明原始 argmax 线，与 gated 蓝线对比：

- **安静期**：灰色噪声均匀散布于整个窗口，无空间集中性
  → 确认为 discretization 噪声，非真实运动，gate 未丢失有效信息
- **运动期**：灰色线集中在某个距离附近，蓝色线忠实跟随

## 四、Lab 4 流水线移植（本 session 早期）

整体 DSP 结构对齐 6.808 Lab 4 Gesture Recognition 笔记本：

| 步骤 | 方法 | 说明 |
|------|------|------|
| 背景去除 | 连续帧差 `np.diff(range_ffts, axis=0)` | 抑制静态杂波，突出运动 |
| 目标 bin 选择 | 均值帧差 profile 的 argmax（≥0.25 m） | 避免近场泄漏主导选择 |
| 距离追踪 | 窗口 argmax + noise gate | 见上 |
| 呼吸提取 | 相位展开 → detrend → 高通 0.05 Hz → 带通 0.1–3 Hz | 独立 channel |

近场截止距离 `MIN_RANGE_M = 0.25 m`，防止 tube 泄漏（直接耦合路径）干扰目标选择。

## 七、已知限制

- **近距离录音（<0.3 m）**：目标 bin 可能与 tube 泄漏重叠，建议用 `--target` 手动指定
- **连续运动追踪**：hold-last-value 对缓慢漂移不友好，需降低阈值至 1.5×
- **呼吸率在运动期无效**：phase 估计假设目标静止，大幅运动期间呼吸率读数不可信
